## 三、课程怎么写(每门语言的流程)

1. **核心大纲**(已完成):`content/outlines/<语种>.json` 或 `content/outlines/<语种>/a1u1.json …`,配 `<语种>.md`(故事线、角色、给写课同事的注意事项)。大纲是**词条总登记处**:写好的课的新词必须和大纲一致(校验会查)。
2. **单元规划**(六门都有了):`content/outlines/<语种>/plan.json`(A1)、`plan-a2.json`(A2)、`plan.md`。规划只有课的类型、标题、能力目标、场景、语法重点,没有词条。工具会跳过 `plan*` 开头的文件。
3. **写课**:一个写课智能体负责
   - A1 第 1–8 单元的新增课(每单元 l06、l07、r01、r02,分第 1–4、5–8 单元两批),或
   - A1 第 9–20 单元每 3 个单元一批(每单元 l01–l08、r01、r02),或
   - A2 每 3 个单元一批(每单元 l01–l08、r01、r02、r03)。
   它先把这些课登记进大纲(每单元一个文件 `content/outlines/<语种>/a1u09.json`,新增课是 `a1-extra-u1-4.json` / `a1-extra-u5-8.json`),再一节一节写课文件 `content/courses/<语种>/a1u9.l01.json`。
4. **写完一批**:负责人跑 `npm run validate -- --lang <语种> --only <语种>.a1u9.,<语种>.a1u10.`(前缀后面带点),通过就提交推送;把报告里新定下的人物细节记进 `content/outlines/<语种>.facts.md`(写课的人写之前都要读这个文件)。
5. **审校**:写完一批就让一个审校智能体审(改错、`review` 标 `ai`、报告写到 `content/reviews/<语种>-*.md`)。报告里"给写课同事的注意事项"后面的写课说明会自动让人去读。
6. **最后收尾**(全部写完以后):每门语言跑 `npm run content:dedupe -- --lang X --write`(去重:后面的课里重复的词改成复习前面那个)、`content:sync-order -- --lang X`、`content:sync-minutes -- --lang X --write`、`npm run validate -- --strict`、`content:hours`(每门 ≥ 200 小时)、`npm run e2e`、iOS / Android 导出;更新 README 的学时表和 `docs/05`。

### 写课时的规则(都写进了任务说明)
- 课时:核心课 18–30 分钟,读物 10–20 分钟(`hours.ts` 按内容算,`estimatedMinutes` 填算出的值)。
- 课文只能用已经学过的词,每句的 `items` 列全;第一人称的短文、信、消息,说话人用写的人;本课的目标表达要让主角说出来;理解题答案位置要分散;不出现酒类、烟草、赌博;电话号码用虚构的。
- **撞词规则**:同一个词规划里排在前面的单元先教,后面的单元改成复习词(`reviewItems`)。几批并行写时,别人还没写完的大纲文件里的词先不用;别人已经定稿(写完)的批次,里面的词可以当已学词用。
- **词条 id 和课 id 永远不改**。

### 任务说明模板(`tools/briefs/`)
- 写课说明用生成器:`SCRATCH_ROOT=<你的临时目录> python3 tools/briefs/gen.py <extra|a1|a2> <语种> <起始单元> <结束单元> <临时子目录名> [高频词说明] [新增课的大纲文件名]`
  - 例:`python3 tools/briefs/gen.py a1 es 9 11 es-u911 > /tmp/es-u911.md`;`python3 tools/briefs/gen.py extra es 1 4 es-x14 "按 content/outlines/es/plan.md 里的高频词对应表放" a1-extra-u1-4.json`
  - 生成器由 `head.md` + `mid-a1.md` / `mid-extra.md` / `mid-a2.md` + `common.md` 拼成;语种专属的写法(标点、称呼、日语分词、韩语罗马音等)在 `gen.py` 的 `LANG` 里。
- 日语、韩语第 1–8 单元的核心课(已经写完)用的是 `ja-core.md`、`ko-core.md`。
- 审校:`review.md`;单元规划:`plan.md`(把 `{LANG}` 等占位符换掉)。
- 启动子智能体时,提示词就写:「你是「语途」的课程编写成员。你的完整任务说明在文件 X 里:先用 Read 把它完整读一遍,然后严格照做。不要执行任何 git 命令。最后给负责人写简洁的中文报告。」再补充当时的协调信息(比如"同事正在写的 a1u12.json 里的词先别用")。
- 接上被打断的批次:用同一份任务说明,补一句「这批课以前写过一部分(content/ 里已经有的文件和大纲),先检查已有的,再接着写完,有问题就改」。

## 六、经验和注意事项

- **子智能体会碰到账号用量上限**("session limit · resets HH:MM UTC"),停下时写到一半的内容都在磁盘上。到点后给它发消息就能接着做(同一个会话里);换了会话就按第三节重新开。
- **不要用全局替换改内容文件**:有一次改韩语一个词的罗马音,把 id 里同样的字母串也替换掉了,导致课和大纲对不上。只改指定字段。
- 提交说明里有英文双引号时,用 `git commit -F -` 加 heredoc,不然 shell 会把引号吃掉。
- 并行写课的子智能体共用临时目录时,每人用自己的子目录(同名文件会互相覆盖)。
- 任务说明里一定写"不要执行任何 git 命令"(只读的也不要),提交和推送由负责人统一做。
- 人物细节表(`content/outlines/<语种>.facts.md`)每完成一批就补,这是几十个人写同一个故事不矛盾的关键。
- 单元测试用的是 `packages/core/test/data` 里固定的示例课,不跟着课程内容变;真实课程由 `npm run validate` 检查。
