# 参考项目评估:泰好说(smallyjh-boop/taihaoshuo)

> 评估日期:2026-10-22,基于 `main` 分支最新提交 `24e84c1`。逐个看了代码、内容格式、文档和 CI 配置。

## 一句话结论

**内容生产流水线和教学设计值得学,技术架构和商业化准备不能照搬。** 它是一位家长给自己两个孩子做的家用 App,目标是"能在家里用",不是"能上架卖"。我们要做的是面向大众、上架苹果和安卓、主打德法英等主流语种的产品,出发点不同,很多地方需要重新设计。

另外有一个硬约束:**这个仓库没有 LICENSE 文件**,法律上默认"保留所有权利",代码和内容都不能直接拿来用。即使作者同意,它的音频(edge-tts 免费声音)也明确不能商用,内容也全部是 AI 写、AI 审,没有母语老师审过。所以新系统只能**借鉴思路,从零实现**。

## 它做得好的地方(值得学)

| 方面 | 具体做法 | 我们怎么用 |
|---|---|---|
| 内容流水线 | 课程"规格 → 装配 → AI 审校 → 十几道自动检查 → 配音 → 发布",全部脚本化 | 照这个思路做,检查项写进 `packages/core/src/validate.ts` |
| 内容校验 | zod 定义格式;检查"课文只用学过的词"、句长按阶段封顶、语块 id 不撞车 | 已实现同类检查,并加了语种规则(德语冠词与性一致等) |
| 学习闭环 | 课时 = 热身复习 + 微课 + 衔接对话 + 拓展词 + 综合练习 + 开口说;课后自动生成练习课 | 保留"学 → 练 → 复习"闭环 |
| 间隔复习 | 用 FSRS 算法(目前最好的开源复习算法) | 同样用 FSRS(`ts-fsrs`),并升级为三方向卡片 |
| 内容体量 | 每门约 200 小时、3000 词、450 篇分级读物 | 说明一个人 + AI 在几周内能铺出很大的量;但质量要靠人 |
| AI 口语老师 | 多家模型可切换(DeepSeek、通义、Kimi……);先在本地过滤求助/隐私信息;没有密钥时退回剧本对话 | 思路可用,但上架国内要用已备案的国产模型 |
| 工程纪律 | 有端到端测试、排版检查(防止字超出屏幕)、按键大小检查;交接文档写得非常清楚 | 学这种习惯 |

## 它的问题(不能照搬的原因)

### 1. 定位:儿童、家庭专用,不是大众产品
- 人物、场景都围绕作者家孩子设计(英语课的主角是一只叫"象象"的小象,奶奶住北京……)。
- 只有三门语言(泰、日、英),**没有德语、法语**,也没有处理德法语核心难点(名词的性、冠词、动词变位、格)的能力。
- 成人学习者最在意的"考试方向"(雅思、歌德、TEF/DELF、JLPT、TOPIK)完全没有。

### 2. 数据格式带着泰语的历史包袱
- 英语课文里外语原文存在叫 `th`(泰语)的字段里:`{"th": "Good morning!"}`。AI 老师的接口也一样。这是从"只做泰语"一路改过来的痕迹,新语种越多越乱。
- 一个语块只有一张复习卡,"认得"和"会说/会写"混在一起,容易出现认得但用不出来。

### 3. 技术架构只适合家用
| 问题 | 细节 | 上架的影响 |
|---|---|---|
| 网页套壳 | Capacitor + WebView;为了连家里服务器开了明文 http 和混合内容(`cleartext: true`、`allowMixedContent`) | 苹果审核对"网页套壳"和不安全连接都很严格;体验也不如原生 |
| 没有苹果版 | iPhone 只能用网页版 | 不能上 App Store |
| 服务器在家里 NAS | 通过 Tailscale 访问,单机 SQLite | 外部用户根本连不上,扩不了容 |
| 主程序过于集中 | `App.tsx` 1154 行、60 个 `useState` | 加功能越来越难 |
| 仓库 2.6GB 音频直接进 git | 克隆一次要十几分钟 | 协作和 CI 都慢;为了免费的 CI 额度把仓库公开了,内容等于全部公开 |
| 课程访问令牌放在网址里 | 会进服务器日志 | 内容保护弱 |

### 4. 内容质量没有经过真人把关
- 自己的待办里第一条就是"真人母语老师审校(目前全部是 AI 审校)"。
- 语音是 edge-tts 免费声音,作者自己写明"不可商用",很多角色借用别人的声音。
- 大量词借用相近的图标(狼用狗、鹿用山羊……)。

### 5. 商业化相关的全部缺失
- 没有付费/订阅、没有手机号/微信/Apple 登录、后台只有一个管理员密码。
- 没有国内上架必需的东西:App 备案、软件著作权、隐私政策与 SDK 清单、未成年人保护、生成式 AI 备案与标识(见 `03-语种选择与上架合规.md`)。
- 没有数据分析(留存、完课率),无法判断哪里需要改。

## 新系统能不能做得更好?

能,而且关键改进点很明确:

1. **真正的原生 App,一套代码上苹果和安卓**:Expo(React Native)+ EAS 云端打包和提交,支持热更新内容和小版本。
2. **语种无关的数据格式**:原文统一叫 `text`;德语的性和复数、日语读音、韩语罗马字等放进"语言包"声明的 `features`,校验器按语言包强制检查。
3. **针对中国学习者的判题**:不是只判"对/错",而是指出"冠词应该是 der 不是 die"、"漏了重音符号"、"德语名词要大写"——这些是中国人学德法西语最高频的错误。
4. **三方向复习卡**(认读、听力、产出),"会认"和"会用"分开计算。
5. **云端架构**:国内云(阿里云/腾讯云)+ 对象存储 CDN 分发课程和音频,内容与 App 分开发版。
6. **内容质量流程**:AI 起草 → 自动检查 → **母语老师审校(状态字段 `review: native` 才能上线)** → 商用授权配音。
7. **成人 + 考试方向**:CEFR A1→B2 主线,外加雅思/歌德/TEF/JLPT/TOPIK 专项。

本仓库已经把第 2、3、4 点做成了可运行、有测试的代码(`packages/core`),并搭好了 App 骨架(`apps/mobile`)。详见 `02-新系统架构设计.md`。
