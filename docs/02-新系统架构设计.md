# 新系统架构设计

## 目标

- 面向中国学习者(以成人、大学生、留学/移民/考试人群为主,青少年为辅)的外语 App。
- 一套代码,上架 **App Store(中国区 + 海外区)** 和 **国内安卓商店(华为、小米、OPPO、vivo、荣耀、应用宝)+ Google Play**。
- 首发语种:英语、法语、德语;随后日语、韩语、西班牙语;再后俄语、意大利语等(理由见 `03-语种选择与上架合规.md`)。

## 总体结构

```
apps/mobile/        App(Expo / React Native / TypeScript),iOS + Android 一套代码
packages/core/      学习引擎(纯 TypeScript,不依赖界面,App 和服务器共用)
  schema.ts           内容格式(zod)
  grading.ts          判题:冠词/性别、重音符号、大小写、笔误、日语读音
  srs.ts              FSRS 间隔复习,三方向卡片
  exercises.ts        从课程自动生成练习
  session.ts          进度、解锁、今日复习、连续天数
  validate.ts         整门课的内容检查
content/
  languages/<code>.json   语言包:文字、冠词表、必须的词条特性、考试、难点提示
  courses/<code>/*.json   课程
tools/              内容检查、生成 App 内置的课程(apps/mobile/src/content/*.generated.ts)、内容加载压测
services/api/       (下一步)服务器
```

### 为什么选 Expo(React Native),不用参考项目的 Capacitor 网页套壳

| | Expo / React Native | Capacitor(WebView) |
|---|---|---|
| 界面 | 原生组件,滑动、键盘、动画更顺 | 网页渲染,低端安卓机卡顿明显 |
| 苹果审核 | 原生 App,风险低 | "只是个网页"有被拒风险(4.2 条) |
| 录音、语音、通知、内购 | 官方模块齐全 | 需要插件,质量参差 |
| 打包和上架 | EAS 云端打 iOS 包,**不需要 Mac** 也能出 iOS 版;`eas submit` 直接提交 | 本地需要 Xcode |
| 热更新 | EAS Update 可推送 JS 和内容更新(仅限不改变 App 主要功能的修复) | 需自建 |
| 团队 | TypeScript 一种语言做 App、引擎、服务器 | 同 |

### 内容格式要点(`packages/core/src/schema.ts`)

- 外语原文统一叫 `text`,中文叫 `zh`;语种特有信息放 `features`(性、复数、读音、罗马字、音标、高低音)。
- 语言包声明需要哪些特性,例如德语 `nounGender: "mfn"` + `requirePlural: true`,校验器就会要求每个德语名词都带冠词、性别、复数,并检查冠词和性别一致、首字母大写。
- 课程类型 `type`:对话、词汇、语法、阅读、听力、角色扮演、测试。加新类型只加播放器,不改引擎。
- 每个课有 `cefr` 等级和 `skills`(听说读写)标签,方便按等级编排和统计技能均衡。
- `review` 审校状态:`draft` → `ai` → `native`。**只有母语老师审过(native)的课才允许正式上线**(发布流程里卡住)。
- 词条 id 和课 id 一旦发布永不改(进度和复习卡靠它)。

### 内置课程怎么打包、怎么加载

写满以后每门语言约 530 节课和读物,6 门约 3,300 节、20MB 以上的 JSON。课程全部随 App 打包(离线能学、发布简单),
但不能像最早那样把所有语种的课都静态 import 进来、启动时再逐节跑 zod 校验——那样一启动就要把 20MB 内容全部建成对象、校验一遍,
手机上又慢又占内存。现在的做法:

- **构建时校验,手机上不校验**:`tools/gen-content-index.ts`(`npm run content:index`)用 App 同一套 zod schema 解析每个语言包、
  每节课、每个口语场景,默认值在这时填好;格式不对就列出来、退出码 1,打包跟着停下。课按 id 推出的顺序(`core/hours.ts` 的
  `orderFromId`)排好。正式版不再在手机上校验;开发版第一次加载某个语种时还会对一遍 schema(改了 schema 忘了重新生成时提示)。
- **每个语种一个文件,用到才解析**:生成 `apps/mobile/src/content/index.generated.ts`(语言包、每个语种的摘要——课数、单元数、
  等级、场景数,以及按语种的加载函数)和 `<语种>.generated.ts`(这个语种全部的课和场景)。加载函数里写的是
  `require("./de.generated")`:Metro 照样把它打进包里(原生和网页都一样),但模块代码第一次 require 时才执行。
  `content/library.ts` 第一次用到某个语种时 `JSON.parse` 一次,建好按 id 查课的 Map 和词条池,之后一直缓存。
  启动、选语种页(`availableLangs`)只看摘要,一节课都不解析;学德语的人永远不会解析法语的课。
- **为什么存成一个 JSON 字符串**:同样的数据写成对象字面量,JS 引擎要执行建对象的代码;一个大字符串交给原生的
  `JSON.parse`,在 V8 里稍快(压测:一个语种 550 节,128 ms 对 146 ms)。代价也要知道:原字符串一直留在内存里
  (V8 里比对象字面量多占约 40%–65%);Hermes 字节码里含中文的字符串按 UTF-16 存,比对象字面量大约 1.8 倍
  (真实内容每个语种约 360KB 对 200KB);网页包两种写法差不多。手机上哪种更快要在真机(中低端安卓)上测;
  要换成对象字面量,只改生成器输出的那一行,懒加载不变。
- **生成文件不提交**(`.gitignore`):全量时十几 MB,而且每改一节课整行都变,几个人同时写课合并时必然冲突、只能重新生成。
  打包器启动时(`apps/mobile/metro.config.js`:开发服务器、`expo export`、`npm run e2e`、EAS 云端打包)和 App 类型检查前
  (`pretypecheck`)都会自动生成,打进包里的永远是 `content/` 当前的样子。
- **长列表**:首页"全部课程"按单元折叠,一次只展开一个单元,不会一次渲染几百张卡片。
- **压测**:`npm run content:bench` 用现有的课克隆出 6 门 × 550 节的假内容,报告生成文件大小、第一次加载的耗时和内存,
  再用真实内容跑一遍;`npm run content:bench -- --web` 另外报告网页包的大小。10-23 的结果(Node,服务器 CPU;
  手机上的 Hermes 会慢几倍):全量时每个语种的生成文件 3.7MB(gzip 1.0MB),构建时校验 3,300 节课 1.7 秒;
  启动时解析 0 节课(旧做法要把 3,300 节全部建成对象再逐节校验,光校验就 250 ms);第一次打开一个语种
  JSON.parse + 建索引约 20–35 ms,之后用缓存;网页包全量约 31MB(gzip 6.8MB,网页版只给团队看界面用)。

### 以后:课程热更新(方案,还没做)

改错字、补翻译、母语老师审完改了几句,不应该等发新版 App、再等商店审核。打算这样做:

1. **服务器给一份哈希清单**:每个语种一个 `manifest.json`,列出每节课的 id、内容哈希(对 zod 解析后的 JSON 算 SHA-256)、
   需要的最低 App 版本和 `schemaVersion`。课程文件按哈希命名(`<课 id>.<哈希>.json`)放在 CDN 上,可以永久缓存。
2. **内置的课也有哈希**:生成器构建时给每节内置的课算同样的哈希,写进摘要,App 不用解析课就能比较。
3. **只下载变了的课**:App 联网、同意隐私政策后,在后台(不挡界面)拉清单,和本机的哈希(内置的,或者以前下载过的)比,
   只下载不一样的那几节。下载来的课在手机上用 zod 校验(网络来的数据必须校验,这是唯一需要在手机上校验的地方),
   存进本机数据库;下次加载这个语种时用它覆盖内置的同 id 课。下载失败、校验不过、App 版本太低,就继续用内置的。
4. **id 永远不变**:热更新只改课的内容;加新课、新单元也可以走这个通道。课程格式变了(`schemaVersion` 升级)要发新版 App。
5. 课程是数据不是代码,苹果和国内各商店都允许这样更新内容。比起 EAS Update(整个 JS 包一起换、服务器在国外),
   自己的清单 + 国内 CDN 能按节更新、下载量小、国内访问快。需要先有服务器和 CDN(花钱,要负责人同意)。

### 学习引擎要点

- **判题**(`grading.ts`):`correct / almost / wrong` 三档。漏重音符号、德语名词没大写、长词一个字母笔误、用 ae/oe/ue 代替 ä/ö/ü、日语用假名写汉字词 → 算"基本正确"并提示;冠词错了 → 判错并指出正确冠词。
- **三方向复习**(`srs.ts`):认读、听力、产出各一张 FSRS 卡;"基本正确"算 Hard 而不是错,不会把复习间隔打回原点。每日复习封顶,防止积压吓跑用户。
- **练习生成**(`exercises.ts`):选意思、听音选意思、中译外输入、选冠词(德法西意)、句子排序、跟读。同一个种子出同样的题,可测试。

### 服务器(下一步)

| 模块 | 方案 |
|---|---|
| 云 | 阿里云或腾讯云,中国大陆区域(个人信息境内存储;ICP 备案) |
| 账号 | 手机号 + 短信验证码、微信登录、**Sign in with Apple**(iOS 上提供第三方登录时苹果要求必须同时提供) |
| 数据库 | PostgreSQL(用户、进度、订阅);Redis(会话、限流) |
| 内容分发 | 课程 JSON 和音频按"语种/版本"打包放对象存储 + CDN;App 首次安装内置第一单元,其余按需下载、离线缓存 |
| 进度同步 | 本地 SQLite 为主,联网时按卡片合并(取复习次数多的那份) |
| 付费 | iOS 必须用苹果内购(订阅);安卓用微信支付/支付宝(各商店规则以审核为准);服务器统一校验收据、管理会员 |
| AI 口语/写作老师 | 国内用已备案的国产大模型 API(DeepSeek、通义千问、豆包等);对话内容标注"AI 生成" |
| 语音 | 合成:商用授权的 TTS(阿里云、讯飞、火山引擎、Azure 等,**预生成**课程音频,不实时调用);识别和发音评测:按语种选择支持德法语的服务,需逐项确认 |
| 后台 | 内容上下架、用户与订阅、数据看板(留存、完课率、各题型正确率) |

### 课程规划(每个语种)

| 阶段 | CEFR | 从零累计学时 | 词汇量 | 主要形式 |
|---|---|---|---|---|
| 入门 | A1 | 约 80 h | 600–800 | 对话课、词汇课、发音课(字母与拼读) |
| 初级 | A2 | 约 200 h | 1500 | 对话、情景任务、短文阅读 |
| 中级 | B1 | 约 400 h | 3000 | 故事、文章、AI 角色扮演、写作批改 |
| 中高级 | B2 | 约 600 h | 5000+ | 文章、新闻、观点表达、考试专项 |

学时数参考各语种官方机构的建议学时,是 App 给学习者预估"什么时候能达到"的依据(`packages/core/src/goal.ts`,语言包可以单独覆盖);上线后按真实数据校准。

## 已完成(本仓库当前状态)

- `packages/core`:内容格式、判题、FSRS 三方向复习、练习生成、进度与解锁、内容校验;
  以及续订相关的学习引擎(见 `04-续订与学习效果方案.md`):学习者画像(弱点、难度、流失风险)、每日计划、
  弱点专练、目标预估与里程碑、分级测试、周报、连续天数与保护卡、学习提醒、会员订阅状态与扣费提醒。65 个测试全部通过。
- `content/`:8 个语言包(英法德西日韩俄意);德、法各 2 节、英语 1 节 A1 示例课(状态都是 `draft`,需要母语老师审)。
- `apps/mobile`:Expo App。新用户引导(目标、水平、每日时间、期限、分级测试)→ 学习计划 → 首页每日计划 →
  上课 / 复习 / 弱点专练 → 周报;会员页(开发模式,不真实扣费)。iOS、Android、网页三端都能打包;
  网页版用浏览器自动化把主要流程完整走过一遍。
