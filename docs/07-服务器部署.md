# 服务器部署

> 2026-10-22(第二轮更新:Apple 撤销授权、TRUST_PROXY、进度紧凑格式)· 负责人:server-core。适用于 `services/api`(Node 22 + Fastify,生产数据库 PostgreSQL)。
> 花钱的事(买服务器、数据库、证书、短信套餐)和用公司身份办的手续(备案、短信签名)要负责人同意,见 `05-决策记录.md`。

## 一、整体结构

```
App ──HTTPS──▶ 负载均衡(阿里云 ALB/CLB 或腾讯云 CLB,挂证书)
                   │ 内网
                   ▼
              服务器容器 × 2(ECS 上的 Docker,或容器服务 / Serverless 应用引擎)
                   │ 内网                         │ 外网 HTTPS
                   ▼                              ▼
              RDS PostgreSQL(主备)          阿里云短信、Apple、微信、AI 模型、语音评测
```

- **地域**:中国大陆(例如阿里云华东 2 上海 / 华北 2 北京)。用户的个人信息和学习数据存在境内。
- **实例**:上线后至少 2 个服务器实例,放在不同可用区;服务器没有本地状态(登录凭证是 JWT,数据都在数据库),可以随时加减实例。
- **服务器启动时自动建表**(可以重复执行)。第一次部署、以及以后改了表结构的版本,先只起 1 个实例,确认启动成功再扩到多个——多个实例同时建表可能互相冲突。

## 二、环境变量

全部来自 `services/api/src/config.ts`。**密钥只放在服务器的环境变量里**:不进代码仓库、不进镜像、不下发给 App。
存放方式:阿里云 KMS 凭据管家 / 腾讯云 SSM,或者服务器上只有 root 能读的 env 文件(`chmod 600 /etc/yutu/api.env`)。

| 变量 | 生产必填 | 说明 | 负责模块 |
|---|---|---|---|
| `NODE_ENV` | ✅ | 必须是 `production`:启动时检查 JWT 密钥、数据库地址,不允许开发用短信,缺了直接启动失败 | — |
| `PORT` | | 监听端口,默认 `8080` | — |
| `DATABASE_URL` | ✅ | `postgres://用户:密码@地址:5432/库名`。生产环境不配会拒绝启动(内置的 PGlite 数据存在容器里,重新部署就没了,只给开发和测试用) | server-core |
| `PGLITE_DIR` | | 只在开发时用:PGlite 数据目录,默认 `./data/pglite`(目录不存在会自动建) | server-core |
| `TRUST_PROXY` | 看部署 | 信任哪些代理的 X-Forwarded-For(决定 `req.ip`,短信按 IP 限流用它)。**默认只信本机和内网地址段**(含阿里云负载均衡用的 100.64.0.0/10),阿里云 ALB/CLB 走内网转发时不用配。也可以写逗号分隔的 IP/网段;`1` = 只信最近一跳(负载均衡的地址不在内网段时用);`true` = 全信(服务器绝不能被直连时才能用);`false` = 不信 | server-core |
| `JWT_SECRET` | ✅ | 登录凭证的签名密钥,至少 32 字节随机:`openssl rand -base64 48`。换掉它所有人都要重新登录 | server-core |
| `ADMIN_TOKEN` | | 后台口令(请求头 `x-admin-token`,`/admin` 页面输入的就是它)。不设则后台关闭。用 `openssl rand -hex 24` 生成 | server-core |
| `SMS_PROVIDER` | ✅ | 生产必须是 `aliyun`(`dev` 会把验证码打在日志里,生产环境启动直接报错) | server-core |
| `ALIYUN_ACCESS_KEY_ID` / `ALIYUN_ACCESS_KEY_SECRET` | ✅ | 阿里云 RAM 子账号的 AccessKey,**只授予短信发送权限**(`AliyunDysmsFullAccess` 或只含 `dysms:SendSms` 的自定义策略) | server-core |
| `SMS_SIGN_NAME` | ✅ | 审核通过的短信签名,例如 `语途` | server-core |
| `SMS_TEMPLATE_CODE` | ✅ | 验证码模板的 CODE(`SMS_` 开头)。**模板里的变量名必须是 `${code}`** | server-core |
| `APPLE_BUNDLE_ID` | ✅ | App 的 bundle id。Apple 登录校验 token 的受众、内购校验都用它。现在的 `com.example.lingocn` 是占位 | server-core / billing |
| `APPLE_TEAM_ID`、`APPLE_SIGNIN_KEY_ID`、`APPLE_SIGNIN_PRIVATE_KEY` | ✅ | **Sign in with Apple 的密钥**(和内购的不是同一把,见第四节第 9 步)。用来在登录时换刷新令牌、注销账号时向苹果撤销授权(苹果审核要求)。私钥是 .p8 的内容,env 文件里换行可以写成 `\n`。不配时 Apple 登录照常,但注销时撤销不了 | server-core |
| `APPLE_APP_ID`、`APPLE_ISSUER_ID`、`APPLE_KEY_ID`、`APPLE_PRIVATE_KEY` | 内购上线时 | App Store Server API 的密钥(.p8 的内容)。多行密钥在 env 文件里的写法以支付模块说明为准 | billing |
| `APPLE_ROOT_CERTS_DIR` | 内购上线时 | 苹果根证书(.cer)所在目录,校验内购签名用;容器里要把这个目录挂载进去,见 `08-支付接入.md` | billing |
| `APPLE_ENVIRONMENT` | ✅ | `Production` / `Sandbox`(默认)/ `LocalTesting`。**正式上线必须设成 `Production`** | billing |
| `WECHAT_APP_ID` / `WECHAT_APP_SECRET` | 微信登录上线时 | 微信开放平台"移动应用"的 AppID / AppSecret。不配则微信登录接口返回"暂不支持微信登录" | server-core |
| `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`、`AI_DAILY_FREE`(默认 12)、`AI_DAILY_PREMIUM`(默认 60) | AI 老师上线时 | 已备案的国产大模型 API | server-ai |
| `SPEECH_PROVIDER`(`azure`/`none`)、`AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION` | 发音评测上线时 | 语音评测服务 | server-ai |

## 三、构建镜像

```bash
# 在仓库根目录(要用到工作区里的 packages/core、packages/billing)
docker build -f services/api/Dockerfile -t yutu-api:$(git rev-parse --short HEAD) .
```

- 镜像:`node:22-bookworm-slim` + ffmpeg(AI 语音模块转音频格式用)+ tini;只装服务器的生产依赖,不含 App 的代码和依赖;用非 root 用户 `node` 运行;生产启动命令 `npm start`;自带健康检查(`GET /v1/health`)。
- Dockerfile 按目录逐个 COPY,本机的 `node_modules`、`.git`、`.env` 不会进镜像;`services/api/Dockerfile.dockerignore` 让构建上下文只传服务器要的东西(BuildKit 会自动用它)。
- 推到同地域的镜像仓库:阿里云**容器镜像服务 ACR**(个人版免费)/ 腾讯云**容器镜像服务 TCR**,服务器用内网地址拉取。
- tag 用 git 提交号,不用 `latest`:出问题时按 tag 回滚。

## 四、阿里云部署步骤

1. **主体和备案**(负责人办)
   - 阿里云账号做企业实名认证。
   - API 域名(例如 `api.<域名>`)在阿里云做 **ICP 备案**:需要先有一台大陆地域的 ECS 等备案资源,审核约 1–3 周;**备案下来之前,域名解析到大陆服务器的 80/443 端口会被拦截**。备案通过后 30 日内做公安联网备案。
   - App 本身要做 **App 备案**(工信部 2023 年起要求),和 ICP 备案用同一主体,见 `03-语种选择与上架合规.md`。
2. **网络**:建 VPC 和两个可用区的交换机。安全组:服务器的 8080 只允许负载均衡访问;服务器不直接暴露公网。
3. **数据库**:RDS PostgreSQL 16 或 17,**高可用版(主备)**,起步 2 核 4G、50 GB ESSD 并开存储自动扩容。
   - 白名单只放 VPC 网段;建库 `yutu`,建一个普通账号给服务器用(不用高权限账号)。
   - `DATABASE_URL=postgres://yutu_app:<密码>@pgm-xxxx.pg.rds.aliyuncs.com:5432/yutu`(内网地址)。
   - 每个服务器实例最多 10 个数据库连接(`db/index.ts`),2 核 4G 的 RDS 连接数足够。
   - 统计按 UTC 日期算,SQL 里都显式写了时区,不依赖数据库的 `timezone` 参数。
4. **运行服务器**(二选一)
   - **ECS + Docker**:2 台 2 核 4G(Alibaba Cloud Linux 3),装 Docker:
     ```bash
     docker run -d --name yutu-api --restart=always \
       --env-file /etc/yutu/api.env -p 8080:8080 \
       -v /etc/lingo/apple-roots:/etc/lingo/apple-roots:ro \
       --log-opt max-size=50m --log-opt max-file=5 \
       <ACR 内网地址>/yutu/yutu-api:<tag>
     ```
     `api.env` 里写 `APPLE_ROOT_CERTS_DIR=/etc/lingo/apple-roots`。
   - **Serverless 应用引擎 SAE 或容器服务 ACK**:直接用 ACR 镜像部署,环境变量在控制台配置(密钥放"保密字典 / 配置项"),健康检查 `GET /v1/health`,至少 2 个实例。
5. **负载均衡 + HTTPS**:应用型负载均衡 ALB(或传统型 CLB 的 7 层监听)。
   - 证书:阿里云数字证书管理服务(免费 DV 证书有效期 3 个月,要定期续;正式运营建议买一年期证书)。
   - 监听 443 → 后端 8080;80 端口重定向到 443;保持"通过 X-Forwarded-For 获取客户端 IP"开启(默认开)。
   - 后端健康检查:`GET /v1/health`。
   - **负载均衡到服务器必须走内网**:服务器默认只相信"来自内网地址的连接"带的 X-Forwarded-For(`TRUST_PROXY` 的默认值),公网直连伪造的不算。部署后发一次验证码,查 `sms_codes` 表的 `ip` 列应该是手机的公网 IP,而不是负载均衡的地址;不对就按负载均衡的实际地址设 `TRUST_PROXY`。
6. **域名解析**:`api.<域名>` CNAME 到 ALB 的域名。App 的 `apps/mobile/app.json` 里 `extra.apiBase` 改成 `https://api.<域名>`。
7. **短信**:阿里云短信服务申请签名(企业资质)和"验证码"类模板,例如:`您的验证码为${code},5分钟内有效,请勿泄露给他人。` 服务器自己的限流是:同一手机号 60 秒 1 条、每天(北京时间)10 条,同一 IP 每小时 20 条;阿里云控制台的发送频率设置不要比这个更严,否则用户会收到"短信发送失败"。
8. **后台**:`https://api.<域名>/admin`,输入 `ADMIN_TOKEN` 查看指标。口令只存在浏览器标签页里(sessionStorage)。建议在 ALB 上给 `/admin`、`/v1/admin/*` 加来源 IP 白名单(公司网络)。订阅类指标不算苹果沙盒(审核、TestFlight)的数据。
9. **Sign in with Apple 密钥**(负责人或有开发者账号权限的人办):Apple Developer → Certificates, Identifiers & Profiles → Keys → 新建,勾选 **Sign in with Apple** 并关联 App 的 App ID → 下载 .p8(只能下载一次,妥善保管)→ 记下 Key ID;Team ID 在 Membership 页面。分别填进 `APPLE_SIGNIN_PRIVATE_KEY`、`APPLE_SIGNIN_KEY_ID`、`APPLE_TEAM_ID`。App 登录时要把苹果给的 `authorizationCode` 一起传上来(接口约定里已有)。

## 五、腾讯云部署步骤

对应关系:云服务器 CVM(或容器服务 TKE / 云托管)+ 云数据库 PostgreSQL(双节点)+ 负载均衡 CLB(7 层,HTTPS)+ SSL 证书 + 容器镜像服务 TCR;ICP 备案在腾讯云做。步骤和上面相同。

- 部署后同样要确认 `sms_codes.ip` 是用户的真实 IP。如果 CLB 转发到服务器用的源地址不在内网地址段(10/8、172.16/12、192.168/16、100.64/10),把 `TRUST_PROXY` 设成 CLB 的地址段(或者 `1`,只信最近一跳),否则所有用户会被当成同一个 IP 限流。
- 短信:目前只实现了阿里云短信。服务器放腾讯云、短信继续用阿里云完全可以(只是一次外网 HTTPS 调用);要换腾讯云短信需要再写一个 `SmsSender`(腾讯云 TC3 签名)。

## 六、数据库备份

- **自动备份**:RDS 每天全量备份 + 日志备份(可以恢复到任意时间点),保留 30 天;开启跨地域备份(复制到另一个大陆地域),防止整个地域出故障。
- **改表结构前**:手动做一次快照,再部署新版本。
- **恢复演练**:每季度一次,恢复到一个新实例,核对 `users`、`progress`、`subscriptions` 的行数和最近更新时间;第一次正式上线前必须演练过。
- **可选的逻辑备份**:`pg_dump -Fc` 定期导出到同地域的 OSS 私有 bucket(服务端加密、生命周期 30 天)。
- 备份里也有个人信息:只放在中国大陆;注销用户的数据在备份过期后自然清除,隐私政策里要写清保留期限。

## 七、日志和监控

- 服务器把 JSON 日志写到标准输出;用日志服务 **SLS**(腾讯云 **CLS**)收集。**网络日志至少保留 6 个月**(《网络安全法》第二十一条)。
- 日志里不记验证码、token、手机号:请求日志只有方法、路径、状态码、耗时和连接 IP;开发用短信(验证码打日志)在生产环境启动会直接报错。
- 告警:
  - 5xx 比例、接口延迟、健康检查失败、实例重启;
  - 日志关键字"短信发送失败"(阿里云余额不足、签名/模板失效、触发阿里云流控);
  - 429 数量突增(有人刷验证码,或者我们的限流太紧——比如移动网络很多人共用一个出口 IP);
  - RDS 的 CPU、连接数、存储、慢查询。

## 九、已知限制

- **学习进度最大 1MB**:同步用紧凑格式(复习卡是数字数组),实测 3000 个词 + 一年的学习日志约 770 KB,大约 4000 个词(B2 前后)才会到上限;到时候再提高上限或改成增量同步。
- 向苹果撤销授权失败(苹果出错、网络断了)时只记日志、照样注销,不会重试;刷新令牌也随注销清掉了,需要的话人工在苹果后台处理。
- 服务器收到停止信号时不会等正在处理的请求完成(`server.ts` 没做优雅关闭);滚动更新时负载均衡要先摘流量再停实例。
- 短信只实现了阿里云。
