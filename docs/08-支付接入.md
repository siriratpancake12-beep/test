# 支付接入

> 2026-10 · 负责人:billing。现状:**iOS 苹果内购的代码已经完成**(App 购买、服务器校验、App Store 服务器通知),等负责人开通账号、在 App Store Connect 配好后联调;**安卓这次不做**,方案见第五节。
> 苹果和各平台的规则经常变,正式提交前以官方最新要求为准。

## 一、整体流程

```
App 付费页 ──StoreKit 2 购买(appAccountToken = 语途用户 id)──▶ App Store
   │                                                            │
   │ ① 把交易(jwsRepresentation)交给服务器                        │ ③ 续费、扣费失败、过期、退款……
   ▼                                                            ▼
POST /v1/billing/apple/transaction                POST /v1/billing/apple/notification(苹果的服务器调用)
   │  校验苹果签名、bundleId、环境;交易的账号标识必须是当前用户        │  校验签名;按账号标识或原始交易 id 找到用户
   ▼                                                            ▼
            服务器:记流水(subscription_events)→ 更新会员状态(subscriptions)
   │
   ② 服务器确认后 App 才 finishTransaction;App 启动、回到前台时按服务器记录对齐本地状态
```

- **以服务器记录为准**。App 本地只做展示和离线兜底。
- **年度会员的 7 天免费试用**是苹果的"推介促销优惠",购买年度会员时苹果按 Apple ID 判断资格、自动生效;试用结束苹果自动扣费(通知 DID_RENEW)。
- **同一件事只算一次**:每个事件有固定 id(交易相关的按交易 id,比如 `apple:tx:<交易id>:start-trial`;通知带来的变化按通知 id),App 上报、苹果通知、苹果重发都只记一行、只应用一次;通知本身按 `notificationUUID` 去重。
- **乱序、重发不出错**:属于更早一期的数据(比如晚到的旧一期退款)只记流水、不改现在的状态。
- **找不到用户的通知先记下**,用户之后上报同一订阅的交易时按时间顺序补上。
- **同一用户排队更新**(App 上报和苹果通知常常同时到)。
- **价格写清楚**:付费页按 core 的 `PRODUCTS` 显示人民币价格;App Store 实际价格不同(比如非中国区 Apple ID)或这个 Apple ID 已经用过试用时,App 在扣费前弹窗说明,用户确认后才购买。

**账号注销后换绑**:一个苹果订阅(原始交易 id)同一时间只属于一个语途账号。原来的账号已经注销(或者账号这一行已经没了)时,同一个 Apple ID 在新账号里恢复购买或重新订阅,订阅就换绑到新账号——交易是苹果签名的,证明这个 Apple ID 拥有这个订阅;注销期间收到的苹果通知先存着,换绑时一起补上,之后的通知都记到新账号。原来的账号还在用时不换绑,仍然提示"这笔购买属于另一个语途账号";只有同一个 Apple ID 在另一个账号里重新付了钱(交易带的是那个账号的标识),订阅才转过去,拿旧交易抢不回来。每次换绑在 `subscription_rebinds` 记一行(原账号 id,已注销的记 `deleted`;新账号 id;时间;不含其他个人信息),原来账号名下的这个订阅同时删掉;账号注销时,这张表里这个账号的 id 也改成 `deleted`。没有账号标识的购买(比如在 App 外兑换的优惠码):没有还在用的主人时,第一个来恢复购买的账号认领(审计来源 `claim_no_token`,原账号记 `none` 或 `deleted`),已经被还在用的账号认领的,别的账号来仍然是冲突。以后接安卓支付时用同样的规则。

代码:`packages/billing`(校验、映射成订阅事件)、`services/api/src/routes/billing.ts`(接口)、`services/api/src/db/billing.ts`(表)、`apps/mobile/src/purchases.ts`(App 购买)、`packages/core/src/subscription.ts`(会员状态机、扣费提醒)。

## 二、App Store Connect 要做的设置(负责人)

### 1. 前提
- 苹果开发者账号(建议公司主体,见决策记录)。
- **协议、税务和银行**:签"付费 App 协议",填银行账户和税务信息。不签的话内购商品在 App 里取不到。
- 建议申请**小型企业计划**(年收入 100 万美元以下,佣金 15%)。
- App 的 Bundle ID 要和 `app.json` 的 `ios.bundleIdentifier`、服务器的 `APPLE_BUNDLE_ID` 一致(现在是占位的 `com.example.lingocn`,正式名称定了要一起改)。

### 2. 订阅群组和两个商品
建一个订阅群组(比如"语途会员"),两个商品都放在这个群组里(同一时间只能订一个,升降级由苹果处理):

| | 年度会员 | 月度会员 |
|---|---|---|
| 产品 ID | `premium_yearly` | `premium_monthly` |
| 时长 | 1 年 | 1 个月 |
| 价格(中国大陆) | ¥298 | ¥45 |
| 级别(群组内排序) | 1 | 2 |
| 推介促销优惠 | 免费,1 周(7 天),所有国家和地区 | 无 |

- **产品 ID 必须和 `packages/core/src/subscription.ts` 的 `PRODUCTS` 一致**,创建后不能改,删了也不能再用。
- **级别**:年度放 1、月度放 2。这样"月度 → 年度"是升级(立即生效,苹果退还月度剩余部分),"年度 → 月度"是降级(下一期生效)。服务器两种都支持,降级后扣费提醒会按下一期的商品和价格写。
- **免费试用**:年度会员 → 订阅价格 → 推介促销优惠 → 付款方式"免费"、时长 1 周。同一个订阅群组每个 Apple ID 只能享受一次,资格由苹果判断。
- **价格**:其他国家和地区可以用苹果的自动换算。以后调价要同时改 `PRODUCTS`(付费页和扣费提醒的价格从那里来),否则 App 会在扣费前弹窗提示"以 App Store 为准"。
- **本地化**:群组和商品的显示名称、描述(简体中文);商品的审核截图用付费页截图;第一次要和 App 版本一起提交审核。
- **账单宽限期**(App → 订阅 → 账单宽限期):建议开,16 天。扣费失败时用户照常使用、苹果继续扣费,服务器已经支持。
- **家人共享:不要开**(开了就关不掉;家人的交易带的是购买者的账号标识,服务器不会给家人开通)。

### 3. App Store 服务器通知 V2
- App 信息 → App Store 服务器通知:**生产服务器网址**和**沙盒服务器网址**都填,版本选 **Version 2**。
- 网址:`https://<API 域名>/v1/billing/apple/notification`(生产和沙盒可以填同一个,服务器按通知里的环境区分;也可以沙盒填测试服务器)。
- 要求:HTTPS、公网能访问、证书有效;服务器在国内的话域名要 ICP 备案。
- 苹果收不到 2xx 会重发(最多几天)。服务器没开通苹果支付时回 503,开通后还能收到重发。
- 配好以后用 App Store Server API 的"请求测试通知"(`POST /inApps/v1/notifications/test`,需要下面的密钥)检查:`apple_notifications` 表里会出现一条 `TEST`。

### 4. App Store Server API 密钥
- 用户和访问 → 集成 → App 内购买项目 → 生成密钥。下载 `.p8`(**只能下载一次**),记下 Key ID 和 Issuer ID。
- 现在的校验用不到它(交易和通知都是苹果签名的,用苹果根证书就能验)。以后要用:请求测试通知、查询订阅状态和交易历史(对账、补数据)、回应退款咨询(CONSUMPTION_REQUEST)、给 App 外购买(比如在 App Store 兑换的优惠码)设置账号标识。
- 放服务器环境变量 `APPLE_ISSUER_ID`、`APPLE_KEY_ID`、`APPLE_PRIVATE_KEY`(.p8 的内容),**不进仓库**。

### 5. 服务器配置

| 环境变量 | 说明 |
|---|---|
| `APPLE_BUNDLE_ID` | App 的 Bundle ID |
| `APPLE_APP_ID` | App 的数字 Apple ID(App Store Connect → App 信息 → Apple ID),生产环境必填 |
| `APPLE_ENVIRONMENT` | `Production` / `Sandbox`;`LocalTesting` 只用于本机 Xcode StoreKit 测试(不校验签名,生产环境会被拒绝) |
| `APPLE_ROOT_CERTS_DIR` | 苹果根证书所在的目录 |
| `APPLE_ISSUER_ID` `APPLE_KEY_ID` `APPLE_PRIVATE_KEY` | App Store Server API 密钥(暂未使用) |

**苹果根证书**:从 <https://www.apple.com/certificateauthority/> 下载 **Apple Root CA - G3**(`AppleRootCA-G3.cer`,必需,App Store 的签名链就追到它),也可以把 Apple Root CA - G2、Apple Inc. Root 一起放进去。放到服务器上的一个目录(比如 `/etc/lingo/apple-roots/`),`APPLE_ROOT_CERTS_DIR` 指向它。证书是公开的,但不进仓库,由部署管理(换证书不用改代码)。测试里用的是现场生成的假证书链,不联网。

- 缺配置时苹果支付不开通:交易接口回 503"支付服务暂未开通",通知接口也回 503(苹果会重发),会员查询照常。
- **生产环境会同时接受沙盒交易**:苹果审核和 TestFlight 用的是沙盒,不接受的话审核时买不了会员会被拒。沙盒交易在流水里 `environment = 'Sandbox'`,**算指标时要排除**。
- 生产环境默认开在线证书吊销检查(OCSP),服务器要能访问苹果的服务器。

### 6. App 配置
- `app.json` 的 `extra.iapEnabled` 设为 `true`(只在接好服务器的版本打开),`extra.apiBase` 指向服务器。
- expo-iap 是原生模块,Expo Go 里没有,要用开发版或正式包:`npx eas-cli build --platform ios`。
- 只有 iOS、打开了 `iapEnabled`、并且已登录时才走真实内购;否则是开发模式(本机模拟开通,不扣钱;接了内购但没登录时会弹窗说明"这次只是模拟")。
- 把 `<PurchaseSync />`(`purchases.ts` 导出)放进 `StoreProvider` 里(`_layout.tsx`),试用转正、续费、退款后本机状态才会自动更新。

## 三、沙盒测试步骤

1. **建沙盒测试员**:App Store Connect → 用户和访问 → 沙盒 → 测试员。用没注册过 Apple ID 的邮箱,地区选中国大陆。测试员设置里可以调续期速度、清除购买记录(重新测试用)。
2. **服务器**:测试服务器 `APPLE_ENVIRONMENT=Sandbox`,配好根证书;App Store Connect 的沙盒通知网址指向它。
3. **装 App**:用 EAS 打开发版或 TestFlight 包(`iapEnabled: true`),装到真机。iPhone 设置 → App Store → 沙盒账户,登录测试员(不用退出自己的 Apple ID)。
4. **按清单走一遍**。沙盒时间是加速的(默认 1 周 ≈ 3 分钟、1 个月 ≈ 5 分钟、1 年 ≈ 1 小时),每一步看 App 和服务器(`subscriptions`、`subscription_events`、`apple_notifications` 三张表):

| 场景 | 怎么做 | 应该看到 |
|---|---|---|
| 年度试用 | 付费页"免费试用 7 天" | App 显示试用期;服务器 `trial`;流水一条 `start-trial`(App 上报和苹果通知只有一条) |
| 试用转正 | 等试用到期 | 通知 `DID_RENEW` → `renewed`,到期时间更新;App 回到前台后更新 |
| 月度购买 | 付费页选月度 | `purchase` |
| 关闭自动续费 | iPhone 设置 → 沙盒账户 → 管理 → 取消订阅 | `DID_CHANGE_RENEWAL_STATUS` → `autoRenew = false`,扣费提醒不再出现 |
| 到期 | 关闭后等到期 | `EXPIRED` → `expired` |
| 重新订阅 | 过期后再买 | `SUBSCRIBED`(RESUBSCRIBE)→ `purchase` |
| 升级 / 降级 | 订阅管理里换年度 / 月度 | 升级立即生效;降级先记下一期商品,续费时换成月度,扣费提醒按月度价格 |
| 扣费失败、宽限期 | Xcode 的 StoreKit 测试(开启"续期时账单重试 / 宽限期") | `grace`(期间照常使用)→ `billing-retry` → 补扣成功回到 `active` |
| 退款 | Xcode StoreKit 交易管理器里退款,或在测试包里发起退款申请 | `REFUND` → `revoked` |
| 恢复购买 | 删掉 App 重装 → 登录 → 恢复购买 | 恢复成会员 |
| 换账号 | 登录另一个语途账号 → 恢复购买 | 提示"这笔购买属于另一个语途账号" |
| 已用过试用 | 清除前用过试用的测试员再点试用 | 扣费前弹窗"这次开通会立即扣费" |

5. **本机 Xcode StoreKit 测试**(不经过苹果服务器,适合调界面和异常流程):服务器 `APPLE_ENVIRONMENT=LocalTesting`(只能在开发环境,不校验签名)。
6. 上线前用 **TestFlight** 再完整走一遍(TestFlight 也是沙盒环境,不扣真钱)。
7. 审核备注里写明:会员需要登录(进度和会员跟着账号走),并提供一个测试账号。

## 四、数据和指标

- `subscriptions`:每个用户一行,`data` 是 core 的 `Subscription`。
- `subscription_events`:事件流水(试用、购买、续费、扣费失败、自动续费开关、过期、退款)。同一件事只有一行;`environment` 区分 Production / Sandbox;`raw` 是苹果给的原始数据(通知类型在 `raw.notification.notificationType`);还没对应到用户的事件 `user_id` 为空。
- `apple_notifications`:收到的每条通知(按通知 id 去重),找不到用户的也在。
- `renewal_sms`:扣费前短信(服务器在到期前 5 天给绑定手机号的会员发,每个账号每一期一行,规则见 docs/07 第八节);注销后 user_id 置空。
- 保存期限:交易流水、通知、换绑记录在这个订阅最后一笔交易和最后一期都结束满 3 年后删掉(`services/api/src/jobs/retention.ts`);订阅状态跟着账号走。
- 算指标时注意:排除 `environment = 'Sandbox'`;试用转付费 = 同一个 `original_transaction_id` 在 `start-trial` 之后出现 `renewed`;苹果延长订阅(RENEWAL_EXTENDED)、撤回退款(REFUND_REVERSED)也记成 `renewed`,需要时按 `raw` 里的通知类型区分。

## 五、安卓支付:方案对比和建议

国内安卓手机大多没有谷歌服务,Google Play 结算只适合海外用户;国内要接第三方支付或厂商支付。这次不实现,下面是方案。

| 方案 | 覆盖 | 自动续费 | 费用 | 要申请什么 | 接入 |
|---|---|---|---|---|---|
| **微信支付 · APP 支付** | 国内所有安卓手机 | 要另外申请"委托代扣"权限,对行业和资质有要求、单独审核 | 一般 0.6%(以签约为准) | 企业主体;微信开放平台账号 + 开发者资质认证(300 元/年)+ 登记移动应用(包名、签名、官网);微信支付商户号(营业执照、对公账户),和 AppID 绑定并开通 APP 支付 | 原生 SDK(Expo 要写配置插件)、服务器下单、回调验签 |
| **支付宝 · APP 支付** | 国内所有安卓手机 | 要另外签约"周期扣款",审核较严 | 一般 0.6% | 企业支付宝账号;开放平台创建应用并签约 APP 支付 | 同上 |
| **华为应用内支付(IAP Kit)** | 华为、荣耀手机;鸿蒙原生应用 | 支持订阅 | 按华为分成 | 华为开发者联盟企业认证、开通商户服务 | 华为 SDK |
| 小米 / OPPO / vivo 联运 | 主要是游戏 | — | 分成高 | — | 非游戏 App 一般不需要 |
| **Google Play 结算** | 海外、有谷歌服务的手机 | 支持订阅 | 订阅 15% | Google Play 开发者账号(25 美元)+ 付款资料 | 小:expo-iap 已经支持 |

**各商店对虚拟商品支付的要求(2026 年的常见口径,提交前以审核意见为准)**
- 苹果:App 内卖会员**必须用苹果内购**。
- 华为:鸿蒙原生应用(HarmonyOS NEXT)里的虚拟商品要用华为 IAP Kit;安卓 APK 上架华为应用市场,非游戏类一般可以用微信支付 / 支付宝,但口径在变,提交前按华为最新的审核指南确认或问商务对接人。
- 小米、OPPO、vivo、荣耀、应用宝:游戏要接各家的联运 SDK;非游戏 App 内的虚拟商品一般允许直接用微信支付 / 支付宝。
- 国内的自动续费:《网络交易监督管理办法》第十八条要求自动续费前 5 天显著提醒;开通和取消要一样方便,App 内要有解约入口。

**建议**
1. **国内安卓第一步用"微信支付 + 支付宝",卖按期会员(1 个月 / 1 年),不做自动续费**,到期前提醒续买。理由:不需要代扣权限(门槛高、审批慢);不会自动扣钱,合规简单、没有"忘了取消被扣费"的投诉,也符合我们"不靠套路"的原则。代价是续费要用户自己点,续订率会低一些,靠到期提醒和学习效果弥补。
2. 华为、荣耀:如果审核要求(特别是以后做鸿蒙原生版),再接华为 IAP Kit。
3. 海外安卓:用 Google Play 结算的订阅(expo-iap 已支持),商品 id 同样用 `premium_yearly` / `premium_monthly`。
4. 有了数据、确实需要自动续费时,再申请微信"委托代扣"、支付宝"周期扣款",并在 App 内做解约。

**到时候要做的开发**:`packages/billing` 加微信、支付宝的回调验签(核对金额、商户号、订单号),映射成 `purchase` 事件(到期时间 = 现有到期和现在里较晚的那个 + 一个周期,再加一个"不自动续费"事件);core 的扣费提醒只针对自动续费,要加"会员快到期"的提醒;服务器加下单接口(订单号、金额由服务器定,不信 App 传的价格)。

## 七、已知不足

- 没有调用 App Store Server API 定期对账(查询订阅状态、交易历史);通知长时间丢失时靠 App 上报和"恢复购买"补。
- 不支持家人共享。
- 在 App 外购买、没有账号标识的交易(比如在 App Store 里兑换优惠码)要等用户在 App 里点"恢复购买"才对应到账号(第一个来恢复的账号认领);以后可以用 API 的"设置账号标识"提前补上。
- 同一笔交易"退款 → 撤回退款 → 再退款"时,第二次退款会被当成重复(极少见)。
- 扣费提醒(App 的通知和服务器的短信)的价格来自 core 的 `PRODUCTS`(人民币);非中国区 Apple ID 的提醒金额不准,以后可以改用苹果续订信息里的续费价格。
